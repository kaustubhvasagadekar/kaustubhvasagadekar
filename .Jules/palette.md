## 2026-07-20 - Choice Widget Accessibility Parity
**Learning:** For choice-based selection widgets containing nested inputs (like custom cards wrapping radio buttons), relying on click event listeners on parent containers breaks keyboard accessibility. Keyboard arrow key navigation natively updates the checked state of the inputs but does not dispatch parent click events, leaving the UI state, layout expansion, and dependent text (e.g., total prices) out of sync.
**Action:** Always bind layout expansions, visual active states, and price calculations to the nested input's `"change"` event. Handle parent card clicks by programmatically updating the input state and dispatching a native `"change"` event, while ensuring event propagation is stopped on `"change"` to prevent event loops.
